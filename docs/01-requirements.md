## 유비쿼터스 언어

> 모든 협업자가 **동일한 언어로 도메인을 이해하고 소통**하기 위한 용어 체계


| 한글 용어   | 영문 용어    | 설명                                                   |
| ----------- | ------------ | ------------------------------------------------------ |
| 회원        | User         | 서비스를 이용하는 사용자                               |
| 상품        | Product      | 판매하는 물건                                          |
| 브랜드      | Brand        | 상품을 판매하는 주체                                   |
| 주문        | Order        | 사용자가 상품을 구매하기 위해 생성하는 요청 단위       |
| 주문 항목   | OrderItem    | 하나의 주문에 포함된 개별 상품 및 수량                 |
| 쿠폰        | Coupon       | 주문 시 할인 혜택을 적용하기 위한 식별자/정책 단위     |
| 좋아요      | Like         | 회원이 특정 상품에 대해 선호를 표현한 상태             |
| 재고        | Stock        | 상품의 판매 가능한 수량                                |
| 포인트      | Point        | 회원이 보유하고 결제 시 사용할 수 있는 자산            |
| 포인트 내역 | PointHistory | 포인트 적립/사용 상세 내역                             |
| 결제        | Payment      | 주문에 대한 금액을 지불하는 행위                       |
| 금액        | Money        | 가격, 할인 등 금액과 관련된 모든 값                    |
| 주소        | Address      | 배송을 위한 주소 정보 (우편번호, 기본 주소, 상세 주소) |

## 회원 (User)

### 회원가입


| METHOD | URI             | 설명     | 인증   |
| ------ | --------------- | -------- | ------ |
| POST   | `/api/v1/users` | 회원가입 | 불필요 |

#### 기능적 요구사항

- 사용자는 `userId`, 성별, 생년월일, 이메일 주소를 입력하여 회원가입을 할 수 있다.
- 회원가입 완료 시 사용자 정보(`id`, `userId`, `email`, `birthday`, `gender`, `createdAt`)가 반환된다.
- 가입된 `userId`는 이후 `X-USER-ID` 헤더로 사용자를 식별하는 데 사용된다.

#### 비기능적 요구사항

- 회원가입 요청은 1초 이내에 처리되어야 한다.
- 오류 상황에서는 명확한 HTTP 상태코드와 에러메세지를 반환해야 한다.
- 민감 정보(이메일 등)는 로그에 마스킹 처리되어야 한다.

#### Happy Path

```
1. 전제조건: 서비스에 가입되지 않은 사용자
2. (사용자) 회원가입 페이지로 이동하여 ID, 이메일, 생년월일, 성별 등의 정보를 입력
3. (클라이언트) 각 입력 필드의 유효성 실시간 검증
4. (사용자) 가입하기 버튼 클릭
5. (서버) 전달받은 데이터 유효성을 다시 한번 검증
6. (서버) ID/이메일 중복 여부 확인
7. (서버) 회원 정보 저장 후 201 CREATED 응답
8. (클라이언트) 회원가입 완료 후 로그인 페이지로 안내
```

#### 제약 조건


| 필드     | 제약 조건                                |
| -------- | ---------------------------------------- |
| userId   | 필수, 영문/숫자 조합, 4~20자, 중복 불가  |
| 성별     | 필수,`MALE` / `FEMALE` / `OTHER`         |
| 생년월일 | 필수,`YYYY-MM-DD` 형식, 과거 날짜만 허용 |
| 이메일   | 필수, 이메일 형식, 중복 불가             |

#### 응답 스키마

| 필드 | 타입 | 설명 |
| ---- | ---- | ---- |
| id | Long | 사용자 PK |
| userId | String | 사용자 로그인 식별자 |
| email | String | 이메일 |
| birthday | String | 생년월일 (`yyyy-MM-dd`) |
| gender | String | 성별 (`MALE`/`FEMALE`/`OTHER`) |
| createdAt | String | 가입일시 (ISO-8601) |

#### Fail Cases


| 케이스             | 설명                                        | HTTP 상태코드               |
| ------------------ | ------------------------------------------- | --------------------------- |
| 필수값 누락        | ID, 성별, 생년월일, 이메일 중 하나라도 없음 | `400 BAD REQUEST`           |
| ID 형식 오류       | 영문/숫자 외 문자 포함 또는 길이 초과/미달  | `400 BAD REQUEST`           |
| 이메일 형식 오류   | 올바른 이메일 형식이 아님                   | `400 BAD REQUEST`           |
| 생년월일 형식 오류 | `YYYY-MM-DD` 형식이 아니거나 미래 날짜      | `400 BAD REQUEST`           |
| ID 중복            | 이미 존재하는 ID로 가입 시도                | `409 CONFLICT`              |
| 이메일 중복        | 이미 존재하는 이메일로 가입 시도            | `409 CONFLICT`              |
| 서버 오류          | DB 연결 실패, 저장 실패 등                  | `500 INTERNAL SERVER ERROR` |

### 내 정보 조회


| METHOD | URI                | 설명              | 인증 |
| ------ | ------------------ | ----------------- | ---- |
| GET    | `/api/v1/users/me` | 내 회원 정보 조회 | 필요 |

#### 기능적 요구사항

- 사용자는 자신의 회원 정보를 조회할 수 있다.
- 조회 시 `id`, `userId`, 성별, 생년월일, 이메일, 가입일시(`createdAt`) 정보가 반환된다.

#### 비기능적 요구사항

- 응답 시간 1초 이내
- `X-USER-ID` 헤더 기반 인증

#### Happy Path

```
1. 전제조건: 사용자는 로그인 한 상태
2. (사용자) 마이 페이지 메뉴 클릭
3. (클라이언트) 서버에 현재 로그인된 사용자의 정보 조회 요청
4. (서버) X-USER-ID 헤더 검증을 통해 사용자 ID 확인
5. (서버) 확인된 사용자 ID 기반으로 회원 정보 조회
6. (클라이언트) 전달받은 데이터로 마이 페이지 화면 구성
```

#### 응답 스키마

| 필드 | 타입 | 설명 |
| ---- | ---- | ---- |
| id | Long | 사용자 PK |
| userId | String | 사용자 로그인 식별자 |
| email | String | 이메일 |
| birthday | String | 생년월일 (`yyyy-MM-dd`) |
| gender | String | 성별 (`MALE`/`FEMALE`/`OTHER`) |
| createdAt | String | 가입일시 (ISO-8601) |

#### Fail Cases


| 케이스        | 설명                    | HTTP 상태코드               |
| ------------- | ----------------------- | --------------------------- |
| 미로그인      | `X-USER-ID` 헤더 없음   | `401 UNAUTHORIZED`          |
| 미로그인      | `X-USER-ID` 헤더가 빈 값 | `401 UNAUTHORIZED`          |
| 사용자 미존재 | 존재하지 않는 사용자 ID | `404 NOT FOUND`             |
| 서버 오류     | DB 연결 실패 등         | `500 INTERNAL SERVER ERROR` |

## 포인트 (Point)

### 포인트 충전


| METHOD | URI                     | 설명        | 인증 |
| ------ | ----------------------- | ----------- | ---- |
| POST   | `/api/v1/points/charge` | 포인트 충전 | 필요 |

#### 기능적 요구사항

- 사용자는 포인트를 충전할 수 있다.
- 충전 금액은 양수여야 한다.
- 충전 완료 시 충전 내역이 기록된다.

#### 비기능적 요구사항

- 응답 시간 1초 이내
- 충전 요청은 트랜잭션으로 처리되어야 한다.
- 동시 충전 요청 시 정확한 금액이 반영되어야 한다.

#### Happy Path

```
1. 전제조건: 사용자는 로그인 한 상태
2. (사용자) 포인트 충전 페이지로 이동
3. (사용자) 충전할 금액 입력 후 충전 버튼 클릭
4. (서버) X-USER-ID 헤더 검증
5. (서버) 충전 금액 유효성 검증
6. (서버) 포인트 잔액 증가 및 충전 내역 저장
7. (서버) 갱신된 포인트 정보 반환
```

#### 제약 조건


| 필드      | 제약 조건                                  |
| --------- | ------------------------------------------ |
| 충전 금액 | 필수, 양수, 최소 1,000원, 최대 1,000,000원 |

#### Fail Cases


| 케이스         | 설명                  | HTTP 상태코드               |
| -------------- | --------------------- | --------------------------- |
| 미로그인       | `X-USER-ID` 헤더 없음 | `401 UNAUTHORIZED`          |
| 금액 누락      | 충전 금액이 없음      | `400 BAD REQUEST`           |
| 금액 범위 오류 | 최소/최대 범위 벗어남 | `400 BAD REQUEST`           |
| 서버 오류      | DB 연결 실패 등       | `500 INTERNAL SERVER ERROR` |

## 상품 (Product)

### 상품 목록 조회


| METHOD | URI                | 설명           | 인증   |
| ------ | ------------------ | -------------- | ------ |
| GET    | `/api/v1/products` | 상품 목록 조회 | 불필요 |

#### 기능적 요구사항

- 사용자는 구매할 상품 목록을 조회할 수 있다.
- 사용자는 특정 브랜드(`brandId`)로 필터링할 수 있다.
- 사용자는 다양한 기준으로 정렬할 수 있다.
  - `latest`: 최신순 (기본값)
  - `price_asc`: 가격 낮은순
  - `likes_desc`: 인기순 (좋아요 수 기준)
- 로그인 여부와 관계없이 접근 가능하다.

#### 비기능적 요구사항

- 응답 시간 1초 이내
- 페이징 처리 필수

#### Happy Path

```
1. (사용자) 상품 목록 페이지 접근
2. (사용자) 필터/정렬 옵션 선택 (선택사항)
3. (클라이언트) 서버에 상품 목록 조회 요청
4. (서버) 조건에 맞는 상품 목록 조회
5. (서버) 상품 목록과 페이징 정보 함께 응답
6. (클라이언트) 상품 목록 화면 구성
```

#### 쿼리 파라미터


| 파라미터  | 타입    | 필수 | 기본값   | 설명               |
| --------- | ------- | ---- | -------- | ------------------ |
| `brandId` | Long    | X    | -        | 특정 브랜드 필터링 |
| `sort`    | String  | X    | `latest` | 정렬 기준          |
| `page`    | Integer | X    | `0`      | 페이지 번호        |
| `size`    | Integer | X    | `20`     | 페이지당 상품 수   |

#### Fail Cases


| 케이스           | 설명                    | HTTP 상태코드               |
| ---------------- | ----------------------- | --------------------------- |
| 상품 없음        | 조건에 맞는 상품이 없음 | `200 OK` (빈 목록 반환)     |
| 잘못된 정렬 기준 | 지원하지 않는 sort 값   | `400 BAD REQUEST`           |
| 서버 오류        | DB 연결 실패 등         | `500 INTERNAL SERVER ERROR` |

### 상품 상세 조회


| METHOD | URI                            | 설명                | 인증   |
| ------ | ------------------------------ | ------------------- | ------ |
| GET    | `/api/v1/products/{productId}` | 상품 상세 정보 조회 | 불필요 |

#### 기능적 요구사항

- 사용자는 특정 상품의 상세 정보를 조회할 수 있다.
- 로그인 여부와 관계없이 접근 가능하다.
- 조회 시 다음 정보가 포함된다:
  - 기본 정보 (이름, 설명, 가격)
  - 상품 옵션
  - 재고 정보
  - 좋아요 수

#### Happy Path

```
1. (사용자) 상품 목록에서 특정 상품 클릭
2. (클라이언트) 서버에 상품 상세 정보 조회 요청
3. (서버) productId로 상품 정보 조회
4. (서버) 상품 정보, 옵션, 재고, 좋아요 수 응답
5. (클라이언트) 상품 상세 화면 구성
```

#### Fail Cases


| 케이스      | 설명                    | HTTP 상태코드               |
| ----------- | ----------------------- | --------------------------- |
| 상품 미존재 | 존재하지 않는 productId | `404 NOT FOUND`             |
| 서버 오류   | DB 연결 실패 등         | `500 INTERNAL SERVER ERROR` |

## 브랜드 (Brand)

| METHOD | URI                        | 설명                  | 인증   |
| ------ | -------------------------- | --------------------- | ------ |
| GET    | `/api/v1/brands/{brandId}` | 브랜드 상세 정보 조회 | 불필요 |

#### 기능적 요구사항

- 사용자는 브랜드 상세 정보를 조회할 수 있다.

## 쿠폰 (Coupon)

### 주문 시 쿠폰 적용


| METHOD | URI              | 설명                  | 인증 |
| ------ | ---------------- | --------------------- | ---- |
| POST   | `/api/v1/orders` | 주문 시 쿠폰 적용(선택) | 필요 |

#### 기능적 요구사항

- 사용자는 주문 요청 시 `couponId`를 포함해 쿠폰을 적용할 수 있다.
- `couponId`가 없으면 쿠폰 할인 금액은 `0`으로 처리된다.
- `couponId`가 있으면 쿠폰을 조회하고 할인 정책(`FIXED_AMOUNT`/`PERCENTAGE`, 최대 할인 금액)을 적용한다.
- 쿠폰 적용 성공 시 쿠폰 상태는 `USED`로 변경되고 사용 시각이 기록된다.
- 이미 사용된 쿠폰은 다시 사용할 수 없다.

#### 비기능적 요구사항

- 쿠폰 조회/사용 처리 과정은 동시성 충돌을 피하기 위해 잠금 기반으로 처리되어야 한다.
- 쿠폰 사용 처리와 주문 생성은 같은 트랜잭션 흐름에서 처리되어야 한다.

#### Happy Path

```
1. 전제조건: 사용자는 로그인 한 상태이며 주문 가능한 상품을 선택함
2. (사용자) 주문 화면에서 쿠폰을 선택함(선택사항)
3. (클라이언트) 서버에 주문 생성 요청 시 couponId를 함께 전달
4. (서버) couponId 존재 시 쿠폰 조회 및 할인 정책 계산
5. (서버) 쿠폰 상태를 USED로 갱신
6. (서버) 할인 금액이 반영된 주문 생성 처리 진행
7. (클라이언트) 주문 완료 화면 표시
```

#### Request Body (쿠폰 포함)

```json
{
  "items": [
    { "productId": 1, "quantity": 2, "price": 10000 },
    { "productId": 3, "quantity": 1, "price": 5000 }
  ],
  "couponId": 101,
  "cardType": "SAMSUNG",
  "cardNo": "1111-2222-3333-4444",
  "callbackUrl": "https://example.com/payments/callback"
}
```

#### Fail Cases


| 케이스        | 설명                                     | HTTP 상태코드     |
| ------------- | ---------------------------------------- | ----------------- |
| 쿠폰 미존재   | 전달한 couponId에 해당하는 쿠폰이 없음   | `404 NOT FOUND`   |
| 쿠폰 재사용   | 이미 사용된 쿠폰으로 재요청              | `400 BAD REQUEST` |
| 서버 오류     | DB 연결 실패 등                          | `500 INTERNAL SERVER ERROR` |

## 주문 (Order)

### 주문 생성


| METHOD | URI              | 설명      | 인증 |
| ------ | ---------------- | --------- | ---- |
| POST   | `/api/v1/orders` | 주문 생성 | 필요 |

#### 기능적 요구사항

- 사용자는 상품을 주문할 수 있다.
- 상품 수량, 상품 옵션 등을 선택할 수 있다.
- 주문 시 다음 처리가 수행된다:
  - 상품 재고 확인 및 차감
  - 포인트 확인 및 차감
  - 주문 정보 저장
  - 외부 시스템 전송 (Mock 처리 가능)

- 주문 처리는 트랜잭션으로 처리되어야 한다.
- 재고 차감 시 동시성 제어가 필요하다.

#### Happy Path

```
1. 전제조건: 사용자는 로그인 한 상태

4. (서버) X-USER-ID 헤더 검증
5. (서버) 회원 정보 조회
6. (서버) 상품 정보 및 판매 상태 확인

8. (서버) 포인트 잔액 확인 및 차감
9. (서버) 주문 정보 저장
10. (서버) 외부 시스템 전송 (비동기)
11. (서버) 주문 완료 응답
```

| ------------ | ----------------------- |
| 주문 상품 수 | 최대 50개               |
| 상품당 수량  | 최소 1개, 최대 10개     |
| 상품 상태    | 판매중 상태만 주문 가능 |

#### Request Body

    { "productId": 1, "quantity": 2, "price": 10000 },
